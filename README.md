# لوحة Nexora لإدارة المقالات والعروض

واجهة عربية متجاوبة تعمل من المتصفح، وتستخدم Firebase Authentication لتسجيل المدير وCloud Firestore لتخزين المقالات وعروض العمولة. اللوحة مستقلة في هذا المجلد ويمكن رفع محتويات `admin/` إلى مستودع واستضافة منفصلين؛ لا ترفع إعدادات مشروعك إلا بعد استبدال القيم التجريبية.

## تثبيت Firebase للتطوير

من جذر مستودع اللوحة شغّل `npm install` لتثبيت Firebase من `package.json`. الواجهة الحالية تستورد Firebase Web SDK كـ JavaScript modules من شبكة Firebase، لذا لا تحتاج إلى خادم Node.js أو خطوة build لتشغيل `index.html`. مجلد `node_modules/` مستثنى من Git.

## إعداد Firebase

1. في مشروع Firebase، أضف تطبيق Web، وأنشئ قاعدة Cloud Firestore.
2. من Authentication فعّل مزوّد **Email/Password** وأنشئ حساب المدير.
3. انسخ `apiKey` و`authDomain` و`projectId` و`appId` من إعدادات تطبيق الويب إلى `firebase-config.js`.
4. انسخ UID الخاص بحساب المدير إلى `adminUid` في `firebase-config.js`، واستبدل `REPLACE_WITH_ADMIN_USER_UID` بالـ UID نفسه في `firestore.rules`، ثم انشر القواعد إلى قاعدة البيانات.
5. أضف نطاق استضافة اللوحة إلى قائمة **Authorized domains** في Firebase Authentication.
6. استخدم استضافة تدعم HTTPS وملفات JavaScript modules، ثم افتح `index.html` وسجّل الدخول.

إعداد Web API Key ليس كلمة مرور أو مفتاحًا إداريًا؛ لا تضع أبدًا service-account key أو أسرارًا في ملفات المتصفح. الصلاحيات الفعلية يفرضها Firebase Authentication وقواعد Firestore. القواعد المرفقة تمنع القراءة والكتابة الإدارية عن أي UID غير المعرّف، وتسمح للزوار بقراءة المستندات المنشورة فقط.

## ربط الموقع

- انسخ إعدادات تطبيق Firebase نفسها إلى `blog/firebase-config.js` في مستودع الموقع.
- ارفع ملفات الموقع، بما فيها `blog/article.html` وملفات `blog/firebase-*` و`blog/cms.css`.
- المقالات المنشورة تظهر في قائمة المدونة وتُفتح على `blog/article.html?slug=...`، وتظهر العروض المنشورة التي رُبطت بالمقال أسفل محتواه.
- تبقى المقالات الثابتة الموجودة حاليًا كما هي. المقالات الجديدة تُحمّل في المتصفح من Firestore؛ لذلك تعتمد إتاحتها على اتصال الإنترنت وإعداد Firebase.

## صيغة المحتوى

محتوى المقال نص عادي آمن: افصل الفقرات بسطر فارغ، واكتب `## عنوان فرعي` للعناوين، وابدأ السطر بـ `- ` لعناصر القائمة. لا يُسمح بإدخال HTML خام.

تُحفظ عروض العمولة منفصلة عن المقالات، ويمكن ربط كل عرض منشور بمقال واحد أو أكثر. يتضمن كل عرض الشركة/المتجر، المنتج، الرابط، نسبة العمولة، كود الخصم، الوصف، ورابط الصورة.

## نقل اللوحة إلى مستودع مستقل

ارفع محتويات هذا المجلد إلى جذر المستودع الجديد، لا المجلد الأب. أبقِ ملفات الإعداد وقواعد Firestore ودليل التشغيل مع اللوحة، ثم عيّن جذر النشر إلى جذر المشروع. لا يحتاج المستودع المنفصل إلى نسخ ملفات الموقع.

> ملاحظة الفهرسة: المقالات المنشأة في اللوحة تُعرض ديناميكيًا في المتصفح، بخلاف المقالات الثابتة الحالية؛ لا تُنشئ هذه الطريقة صفحة HTML مولّدة مسبقًا لكل مقال.
